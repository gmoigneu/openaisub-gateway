# OpenAI subscription gateway

Status: approved architecture, implementation in progress. Initial architecture approved by the owner on 2026-10-03. Public inference behind the owner's existing Caddy HTTPS proxy approved on 2026-10-04.

Governing issues: [initial gateway #1](https://github.com/gmoigneu/openaisub-gateway/issues/1), [public Portainer deployment #3](https://github.com/gmoigneu/openaisub-gateway/issues/3).

## Outcome

One owner runs a Go gateway in Docker, independently or beside their Mastra agents. Agents use separate revocable gateway keys to make inference requests against the owner's OpenAI subscription. OpenAI credentials never reach agent clients.

## Boundaries

- One owner, one active OpenAI account/workspace, one gateway process and persistent local SQLite volume.
- Private API at `http://gateway:8080/v1` by default. An optional Compose override publishes inference on host loopback for testing, with a configurable host port. An optional Docker Standalone Portainer stack exposes inference through the owner's existing Caddy HTTPS proxy. A separate admin listener is published on host loopback only.
- Support Responses and dynamic Models endpoints. No Chat Completions, embeddings, billing fallback, token accounting, content logs, stored conversations, hosted tool execution, public administration, bundled proxy, or project-managed TLS.
- Mastra executes tools and supplies conversation history. The gateway does not run tools.
- Apache-2.0 source and non-root Linux containers for amd64 and arm64.

## Architecture

One binary embeds the dashboard. Packages isolate OAuth, encrypted SQLite persistence, inference forwarding, and server/CLI composition. Use Go's HTTP server and a pure-Go SQLite driver. Avoid a frontend build system.

The API authenticates random 256-bit client keys, stored only as SHA-256 digests. Keys have names, creation dates and immediate revocation. A separate administrator secret protects the dashboard. Browser sessions are bounded and HTTP-only with SameSite protection and CSRF validation. Admin routes are absent from the inference listener.

Administrator pages use `Referrer-Policy: same-origin` so browser form posts retain their origin while cross-site referrers remain suppressed. Reject absent, opaque (`null`), and foreign origins for login and authenticated mutations; authenticated mutations also require their session's form token.

Persist credentials encrypted with AES-GCM using a separately mounted 32-byte secret. Persist a stable UUID host identifier and the issued OAuth registration. Keep SQLite files owner-only. Rotate credentials atomically and reject stale writes. Only one serving process may own a data directory. Restarts preserve registration and usable credentials.

## Sign-in and renewal

Use official Sign in with ChatGPT for open-source apps. Initial authorization uses `dynamic_agent_client`, the stable host ID, actual app name, PKCE S256, state and nonce. The loopback callback uses `127.0.0.1`. Exchange with the issued client ID, validate the ID token using OpenAI JWKS, issuer, audience, nonce and expiry, and require `chatgpt.tokens.use.direct` plus a refresh token.

The CLI login helper runs beside the browser. For a remote deployment, it obtains the target host registration and imports the result over SSH through the container's admin command. It can target a Compose directory or a running container name or ID; `--directory` and `--container` are mutually exclusive. Container targeting also works locally and does not depend on Portainer's internal working directory. Tokens travel over stdin, never command arguments or printed output. The remote instance owns subsequent refreshes. No manual token copying is required. Reauthentication preserves the account/client mapping and validates identity before replacement.

Persist an initial issued client ID separately before token exchange, so a failed exchange reuses that registration. Do not treat pending registration as a validated account. Credential imports are idempotent across transport retries and must not replace newer rotated tokens with an earlier import. If transfer cannot complete, attempt revocation of the abandoned renewable session and report unconfirmed cleanup.

Renew near expiry using the saved issued client ID and resource `https://api.openai.com/v1`. Serialize renewal and atomically persist rotated tokens. Temporary failures retain credentials. Terminal refresh errors remove unusable tokens while preserving registration and show reconnect-required status. Disconnect attempts remote revocation and reports unconfirmed revocation. Never automatically switch billing methods.

Once started, renewal and its persistence have bounded lifetimes independent of an inference caller's cancellation. Shutdown allows that bounded operation to finish.

## Inference contract

- `POST /v1/responses` forwards only to the fixed official public Responses endpoint. Replace client authorization with the current OAuth bearer. Do not forward caller routing, organization, cookies or arbitrary credential headers.
- Upstream requests use `store:false`, `stream:true`, and full-history array input. Normalize scalar text input into a user message. Reject explicitly requested storage, persisted history, unsupported options and unsupported hosted tools with useful API errors.
- Support function tool round trips and JSON schema output only to the extent established by upstream contract tests. Namespace conversion must preserve function names and call IDs; never execute tools. Document every conversion.
- Stream SSE with prompt flushing and cancellation. For `stream:false`, collect the terminal response into standard Responses JSON, with bounded memory. An interrupted stream is not success. Preserve upstream terminal failure/incomplete events and request IDs. Never replay inference automatically, including after a stream begins.
- Preserve upstream pre-stream status and body, including nonstandard error envelopes. Local errors use the OpenAI error envelope. Do not retain response bodies or aggregate usage; pass upstream usage fields through unchanged.
- `GET /v1/models` fetches the account-specific catalog and maps `models[].slug` into standard `data[].id`. Cache briefly by active registration, invalidate on changes, and never ship a hardcoded fallback catalog. Model selection remains an upstream decision.
- Bound request sizes, headers and buffered responses. Apply connection/header deadlines without a short global stream timeout. Shutdown drains or cancels ongoing requests cleanly.

## Dashboard and setup

Provide connection status, connect instructions, disconnect, and create/list/revoke keys. Display each new client key once. No analytics, prompt history or token counters. Use server-rendered HTML and minimal browser code, with no third-party assets.

Provide Compose configuration with named persistent volume, separate secret files, inference port available only to sibling containers by default, and localhost-only admin publication. Provide an initialization command that creates missing secrets with restrictive permissions without overwriting existing secrets. Document local and SSH-assisted login, backup/restore, key loss and reconnect recovery.

The owner also approved optional host access for testing. Supply `compose.host.yaml` to publish inference at `127.0.0.1:8080`, with `GATEWAY_HOST_PORT` selecting another host port. Client API key authentication remains required. The default Compose configuration does not publish inference, and disabling the override removes that host binding without deleting state.

## Public Portainer deployment

Follow [ADR 0003](../adr/0003-public-inference.md). Provide a Docker Standalone stack with one non-root gateway, a persistent named volume, and separate read-only secret files at absolute host paths. Build the preview image on the target Docker host; no published registry image is assumed. Keep the private Compose setup unchanged.

Use the owner's existing Caddy proxy for HTTPS termination. Route only `/v1/models` and `/v1/responses`, with all other public paths returning 404. Keep gateway API-key authentication on every supported inference request, including models served from cache. Missing, invalid and revoked keys return 401. The administrator password and upstream credentials do not authenticate clients. Do not add TLS handling to the gateway.

For container-based Caddy on the same Docker host, connect both services to an existing external Docker network and publish no host inference port. For host-based Caddy on the same host, publish inference only on `127.0.0.1`. Access the dashboard through an SSH tunnel to its loopback host port. Do not publish the dashboard or health check through Caddy. Containers on the shared proxy network remain trusted and can reach container listeners.

Preserve SSE flushing and cancellation through the proxy. Bound request bodies and headers; do not add a short global stream deadline. Do not log keys, OAuth credentials, request bodies or model output. Keep registration and credential import on the private administration path.

One valid client key can consume the owner's subscription capacity. Per-key quotas, rate limits, shared-service hosting and network denial-of-service protection are outside this change. The operator owns DNS, existing Caddy configuration and host access controls.

Acceptance includes public rejection of missing, invalid and revoked keys; public 404 responses for health and admin paths; authenticated model access; restart persistence; local and SSH container onboarding; safe SSH argument handling; streaming and cancellation; and the repository's Go, Mastra and container checks. The deployment guide must cover setup, configuration, key revocation, backups and updates.

## Delivery and acceptance

1. Establish the spec, issue, ADRs and reproducible Go tests. Build OAuth and forwarding against controlled HTTP fixtures.
2. Verify a real Mastra agent against the gateway: generate, stream, a multi-step function call, structured JSON, cancellation, and upstream failures. Pin the fixture's dependency versions.
3. Complete persistence, dashboard, CLI onboarding, packaging and CI. Verify restart recovery, concurrent refresh, rejected/stale credentials, key revocation, admin isolation and secret redaction.
4. Before claiming v1 ready, the owner must complete live OpenAI sign-in and a subscription-backed Mastra tool round trip. Record the result, model and tested package versions without credentials or prompts. Offline tests cannot establish account eligibility or preview availability.

No product scope expansion is authorized by a failing preview capability. Record the evidence and seek a decision if the documented upstream cannot support the approved contract.
